Pod网络简介

Pod是Kubernetes的最小调度单位。Pod是由一个或多个容器构成，它们彼此共享存储和网络，被共同调度，并在同一上下文里运行。位于同一个Pod里的这些容器，就好比是容器技术出现之前，运行在同一物理机上的多个彼此相关的应用程序。因为Pod里的容器是共享网络的。准确地说是共享同一个network namespace，所以对外只有一个IP地址；同时，彼此之间又可以访问。

让我们创建一个多容器的Pod。它包含一个nginx容器和一个busybox容器。

# multi-container-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: multi-container-pod
spec:
  containers:
    - name: container-1
      image: busybox:latest
      command: ['sh', '-c', 'echo "Busybox is running" && sleep 3600']
    - name: container-2
      image: nginx:latest
1
2

# 执行命令，创建Pod
kubectl apply -f multi-container-pod.yaml

创建Pod，将会发生以下事情：

1、创建一个Pod时，容器运行时首先会为容器创建一个网络命名空间。

2、然后，CNI接管并分配一个IP地址。

3、最后，CNI将容器连接到其他虚拟网络设备（veth0、eth0等）。

Pause容器

如上图，我们发现除了nginx和busybox容器，还有一个pause容器。为什么会有pause容器，pause容器又是做什么的？

之前我们提到，Pod中的容器是共享网络的，这个共享的网络实际上是pause容器所创建的。

Pause容器有以下作用：

  • 创建network namespace, 并共享network namespace给pod中其他容器。
  • Pause容器是第一个创建的容器，因此它也是Pod的第1号进程（PID 1）。并负责处理僵尸进程的回收。
  • Pause容器负责维护Pod的IP地址。
  • Pause容器的生命周期和Pod一样。只有当Pod被删除，Pause容器才会被终止。

为什么选择pause容器的网络作为Pod的共享网络呢？

Pause容器代码很少，逻辑简单，启动后立即进入Sleep状态。由于容器在Sleep模式下几乎很难出现错误，因此从安全，稳定的角度考虑，选择Pause是一种更正确的选择。

试想一下，假设我们选择其他某个应用容器来承担这个角色，一旦这个容器因为某些原因而崩溃，那么Pod里其他容器的网络就无法连通，新的容器也无法加入到Pod的网络里来。

可以看到，输出结果已经找不到eth0@if5和IP信息了。这个时候虽然busybox2还在运行，但是没有网络，无法和外界通信了。

正是由于这样的原因，对于承担Pod网络环境的容器而言，它必须简单小巧，稳定不容易出错崩溃。

只要不主动删除Pod，Pause都会一直存活。Pod的生命周期也就是Pause容器的生命周期。
